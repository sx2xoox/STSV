# STSV 코어 설계

STSV 코어는 스트리머 서버에서 운영할 **모든 콘텐츠의 공통 기반**입니다.

## 0. 운영 방식

- 콘텐츠는 **하나씩, 중기적으로** 운영합니다. 시즌마다 가볍게 규칙만 바꾸는 방식이 아닙니다.
- 다음 콘텐츠는 이 공통 플러그인을 기반으로 **새로 제작**합니다. 그래서 공통 플러그인에는 어떤 콘텐츠든 다시 쓰는
  부품(아이템, 가구, 메뉴, 저장소, 기록, 리소스팩 ...)만 두고, 콘텐츠 규칙은 콘텐츠 쪽 플러그인과 콘텐츠 팩에 둡니다.
- 콘텐츠 후보: 경제 서버(일반적인 마인크래프트 경제 서버: 상점, 시장, 거래, 직업 등), 왕국 쟁탈전, 좁혀지는 세계,
  경제 RP, 협동 레이드, 세계관 연재형. 어떤 콘텐츠를 할지는 아직 정하지 않았습니다.
- 콘텐츠를 정하면, 그 콘텐츠가 요구하는 것 중 다른 콘텐츠에도 쓸 만한 것(예: 경제 API)만 공통으로 올립니다.

## 1. 구조

```
[stsv-core]  공통 플러그인 (이 저장소의 plugin/)
  ├─ 모듈 시스템 (StsvModule): 기능 단위로 켜고 끄고, 리로드
  ├─ 저장소 (SQLite 기본 / MySQL): 테이블 버전 관리, 비동기
  ├─ 콘텐츠 팩: 아이템 / 가구 / 레시피 / 3D·2D 모델 / 메뉴 / 칭호 / 보스
  ├─ 메뉴: YAML + 배경 PNG 로 전용 UI (폰트는 자동 생성)
  ├─ 기록: 프로필, 통계, 칭호, 명예의 전당, 콘텐츠 기간
  ├─ 문구: messages.yml (콘텐츠마다 말투를 바꿀 수 있음)
  └─ 리소스팩: 자동 빌드 + 내장 호스팅 + 접속 시 자동 전송

[콘텐츠 플러그인] (예: stsv-economy)
  └─ stsv-core 에 의존. 자기 모듈, 콘텐츠 팩(contents/economy/ 등), 메뉴, 통계만 추가
```

콘텐츠 플러그인에서는 이렇게 사용합니다.
```java
STSVPlugin core = STSVPlugin.get();
core.modules().register(new EconomyModule());                       // 자기 기능
core.db().migrate("economy", List.of(List.of("CREATE TABLE ...")));  // 자기 테이블
core.menus().open(player, "economy:shop", new ShopMenu());          // contents/economy/menus/shop.yml
core.profiles().add(player.getUniqueId(), "money_earned", 1500);     // 기록 (기간별 + 전체)
player.sendMessage(Lang.msg("economy.bought", "item", name));        // messages.yml
```

## 2. 현재 구현됨

| 기능 | 설명 |
|---|---|
| 콘텐츠 팩 | `plugins/STSV/contents/<팩>/`. 첫 실행 때 기본 팩이 자동 설치됨 |
| 커스텀 아이템 | 이름(MiniMessage), 설명, 모델, 최대 스택, 반짝임, 내구도 무한 |
| 3D 모델 | `.bbmodel`을 폴더에 넣으면 자동 변환됨 (큐브, 회전, 발광, 표시 설정) |
| 2D 모델 | `.png`를 넣으면 일반/손에 든 모양 모델이 자동 생성됨 |
| 가구 | 회전 설치, 여러 블록 크기, 충돌(배리어), 클릭 판정, 부수면 회수 |
| 가구 API | 설치/상호작용/파괴 이벤트, `FurnitureBehavior`로 기계 로직 연결 |
| 레시피 | 조합(모양/무형), 화로, 용광로, 훈연기, 모닥불, 석재 절단기 |
| 레시피 보호 | 커스텀 아이템이 바닐라 레시피 재료로 쓰이는 것을 차단 (복사 버그 방지) |
| 리소스팩 | 빌드 → SHA-1 해시 → 내장 웹서버로 배포 → 접속 시 전송. 내용이 같으면 해시도 같음 |
| 관리 | `/관리 지급, 아이템목록(GUI), 목록, 정보, 리로드, 리소스팩` (모든 명령어 한국어) |
| 레시피 편집기 | `/관리 레시피 생성 <id> <종류>`: 상자 GUI에 재료와 결과물을 넣고 저장하면 바로 등록 (`recipes/editor.yml`) |
| 화로 연료 | 아이템 `fuel: 3200` 또는 `/관리 연료 설정 <틱>` (`fuels.yml`). 커스텀 아이템은 설정한 경우에만 연료로 탐 |
| 설치 미리보기 | 가구를 들면 설치될 자리에 모델(테두리 발광)과 바닥 범위가 표시됨. 초록 = 설치 가능, 빨강 = 불가. 본인에게만 보임 |
| 앉기 | `furniture.seat` / `seats` 설정. 우클릭으로 앉고, 내리면 가구 앞쪽에 섬 |
| 전용 동작 아이템 | 활, 쇠뇌, 낚싯대, 방패, 검, 갑옷(착용 모습 포함). 바닐라 동작을 그대로 상속 |
| 기본 콘텐츠 자동 업데이트 | 새 jar로 바꾸면 기본 팩이 갱신되고, 빠진 파일은 삭제됨. 직접 수정한 파일은 보존 |
| 음식 | `food:`: 허기, 포만도, 먹는 시간, 동작, 소리, 효과, 반환 아이템, 재사용 대기시간, 추가 회복 |
| 스킨북 | `skin:`: 우클릭으로 창을 열고 도구를 넣으면 겉모습만 교체. 인챈트, 내구도 유지. `/관리 스킨 해제`로 해제 |
| 치장 + 옷장 | `cosmetic:`: 실제 장비 위에 보이기만 함(본인 F5 포함). 옷장 구역에서 `/옷장` → 메뉴. 치장 클릭 = 착용(착용 중이면 벗기, 미보유는 미리보기) → 메뉴가 닫히고 관전 카메라로 마네킹만 보임(몸, 손, 단축바 없음). 웅크리기 = 메뉴, 나가기 버튼 = 나가기. 메뉴가 열려 있는 동안만 크리에이티브 모드: 관전 모드에서는 서버가 메뉴 클릭을 무시하고, 모험 모드에서는 손에 든 아이템과 경험치 바가 보이기 때문. 크리에이티브의 아이템 생성/버리기는 옷장 안에서 막고, 손은 본인 화면에서만 빈손으로 보임. 카메라를 먼저 붙인 뒤 메뉴로 넘어가므로 첫 메뉴부터 단축바가 안 보임 |
| 옷장 메뉴 | 큰 상자(54칸). 치장 7×4 = 28칸, 넘치면 페이지(이전/다음). 칸 배치와 문구는 `menus/wardrobe.yml` (메뉴 프레임워크) |
| 전용 UI | 폰트 글리프 배경(176×222) + 리소스팩 버튼 아이콘. 그림/설정/글리프 위치가 서로 맞는지 테스트로 확인 |
| 보스 | `bosses/*.yml`: 관절별 3D 모델(디스플레이 엔티티) + 키프레임 애니메이션(부드러운 전환, 머리가 대상을 봄) + 패턴(내려찍기, 돌진, 던지기, 경고 표시 포함) + 페이즈(모델 교체, 강화) + 보스바 + 피해량 순위 + 드롭. 판정은 보이지 않는 철 골렘 |
| 저장소 | `database:` SQLite(파일 하나) 또는 MySQL/MariaDB(여러 서버 공유). 모듈마다 번호 붙은 테이블 변경(`migrate`)을 한 번씩만 적용. 게임 틱을 막지 않도록 DB 전용 스레드에서 실행. 드라이버는 서버가 처음 켤 때 받음 |
| 치장 보유 → DB | 예전 `data/cosmetics.yml` 은 처음 켤 때 자동으로 DB로 옮기고 `.imported` 로 이름 변경 |
| 메뉴 프레임워크 | `contents/<팩>/menus/*.yml`: 칸 배치(글자 그림), 버튼(동작, 아이콘, 이름, 설명, 쓸 수 없을 때 모습), 페이지 목록, 배경 PNG. 배경 폰트는 리소스팩 빌드 때 자동 생성. 모듈은 `MenuHandler` 로 목록과 동작만 채움 |
| 문구 파일 | `messages.yml`: 플레이어에게 보이는 문구. 빠진 줄은 기본 문구. 관리자 명령어 출력은 코드에 둠 |
| 프로필 / 통계 | 플레이 시간, 사망, 처치, 블록, 보스 처치/피해량을 자동 집계. 콘텐츠는 `profiles().add()` 로 자기 통계 추가. 메모리에 모았다가 1분마다 묶어서 저장 |
| 콘텐츠 기간 | `/관리 기간 시작 <id> <이름>` ~ `종료`. 통계는 전체 + 기간별로 따로 쌓임. 끝날 때 부문별 상위 N명을 명예의 전당에 기록 |
| 칭호 | `contents/<팩>/titles/*.yml`. 채팅과 탭 이름 앞에 표시. `/프로필` 에서 장착. 관리자 지급(기본 팩에는 테스트 칭호 3개만). 보스 정의에 `title:` 을 쓰면 처치 참여자에게 지급 |
| `/프로필`, `/명예의전당` | 기록과 칭호 메뉴 / 지난 콘텐츠의 순위 |
| 설정 기본값 | 기본값은 jar 안의 `config.yml` 한 곳에만 있음(코드에 기본값을 두지 않음). 예전 config 파일에 새 항목이 없어도 최신 기본값이 적용됨. 테스트로 검사 |
| 보스 연계 패턴 | `type: sequence`: 단계별 애니메이션 + 판정 + 지연(번쩍임 예고) + 이동/도약 + 잡기(구출 가능) + 충격파(점프 회피) + 안전 구역 외우기. 조건부 패턴(등 뒤, 높은 곳, 회복 시도). 판정이 실제 칼 궤적과 맞는지 테스트로 검사 |
| 가구 중복 설치 방지 | 같은 플레이어의 설치는 6틱(0.3초) 안에 한 번만 (우클릭이 두 번 들어오는 경우) |
| 치장 보유 | 계정 단위 보유 목록(`plugins/STSV/data/cosmetics.yml`, 시즌 초기화와 무관). 교환권(`voucher:`)을 우클릭해서 등록, 관리자 지급, 등급 4단계, 획득 연출. 미보유도 미리보기 가능, 착용만 불가 |
| 무기 효과 | `effects.swing`: 좌클릭(공격) 때 시선 기준 대각선(오른쪽 위 → 왼쪽 아래) 참격. `effects.charge`(선택): 우클릭 차지 후 큰 참격 |
| 움직이는 모델 | 애니메이션 텍스처, 회전 부품 |
| 가구 엔티티 절감 | 클릭 판정을 정사각 기둥 단위로 합침(2×2×1 기계 4→2, 3×3 바닥 9→1). 판정 범위, 겉모습 동일 |
| 경제 | 잔액(정수 G) + 모든 돈 움직임의 거래 기록(누가, 누구에게, 얼마, 종류, 이유). 종류: 생성(FAUCET), 소멸(SINK), 거래(TRANSFER), 수표, 관리. 잔액은 메모리에서 바로 판단하고 DB 에는 `balance = balance + ?` 로 기록(순서가 바뀌어도 합이 맞음). 콘텐츠는 `economy().deposit / withdraw / transfer(..., reason)` 만 사용. `BalanceChangeEvent` |
| Vault 호환 | Vault 가 설치돼 있으면 STSV 돈을 Vault 경제로 등록: 다른 상점/경매/직업 플러그인이 그대로 씀 (정수 G: 출금 올림, 입금 내림, 거래 기록 이유 "vault") |
| 수표 | `/수표 <금액>`: 돈을 아이템으로(분실, 도난, 뇌물 가능). DB 에서 "아직 입금 안 됨"일 때만 입금 처리 → 복사한 수표는 무효. 우클릭 순간 아이템을 먼저 빼서 연타로 두 번 입금 불가 |
| 경제 관리 | 지급/회수/설정, 거래 기록, 최근 N분 되돌리기(양쪽 모두, 수표 무효화 포함), 24시간 통계(생성/소멸, 총 통화량, 지니 계수) |
| HUD | 액션바 상태 줄: 콘텐츠가 `hud().line(id, 순서, 플레이어 → 문구)` 로 항목 추가(기본: 잔액). 일회성 안내는 `HudModule.flash()` 로 보내면 상태 줄이 3초 비켜줌. 이벤트 보스바 `hud().bar(...)` (나중에 들어온 사람에게도 보임) |
| 콘텐츠 플러그인 연결 | 콘텐츠 플러그인(예: 경제 서버)은 `onLoad` 에서 `ContentModule.registerBundle(this, getFile())` 로 자기 jar 의 `default-content/` 를 등록(코어와 같은 방식으로 설치·업데이트, 기록 파일은 따로), `Lang.register(this)` 로 자기 messages.yml 을 추가, 모듈은 코어의 `modules().register()` 로 넣어 `/관리 리로드` 를 함께 받고, 꺼질 때 `modules().unregister()` |
| 코어 이벤트·API 추가 | `BossDefeatEvent`(전리품을 가로채 경매로), 돈 종류 `ESCROW`(입찰금 보관), 메뉴 핸들러 `onPlayerInventoryClick`(상점에서 내 인벤토리 클릭 = 팔기), `endPeriod(추가 부문)`(순자산을 명예의 전당에), `ownedTitles()` |
| 테스트 초기화 | `/관리 초기화 경제\|기록 확인`: 재설치 없이 반복 테스트 |
| 보호 플러그인 호환 | 가구 설치 전에 BlockPlaceEvent를 발생시켜 다른 보호 플러그인의 판단을 따름 |

## 3. 다음 공통 작업 후보 (콘텐츠를 정한 뒤 필요한 것만)

| 후보 | 언제 필요한가 |
|---|---|
| 치지직 연동 (채팅, 후원 → 서버 이벤트, 시청자 투표) | 모든 콘텐츠. API 이용 신청과 승인이 먼저 필요 |
| 스트리머 보호 (오프라인 보호, 좌표 숨김, 따라잡기 보정) | PvP 가 있는 콘텐츠 |
| 팀 / 영토 | 왕국 쟁탈전 |
| 하이라이트 기록 (클립용 시각 기록) | 방송 편집 지원 |
| 운영 도구 (공지, 예약 재시작, 백업) | 실제 운영 시작 전 |

## 4. 게임 안에서 아직 확인하지 못한 것

개발 환경에서 서버를 실행할 수 없어서, 실제 26.3 API로 컴파일하고 단위 테스트까지만 통과했습니다. 첫 실행 때 아래를 확인해야 합니다.

| 항목 | 확인 방법 | 문제가 있으면 |
|---|---|---|
| 가구 모델이 정면을 바라보는지 | 용광로를 네 방향으로 설치 | `furniture.display-yaw-offset: 180` |
