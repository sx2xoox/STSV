# STSV 코어 설계 (가안)

STSV 코어는 앞으로 만들 모든 시즌 서버(타이쿤, 왕국 쟁탈전, 좁혀지는 세계, 경제 RP, 협동 레이드, 세계관 연재형)의 **공통 기반**입니다.

## 1. 구조

```
[stsv-core]  공통 플러그인 (이 저장소의 plugin/)
  ├─ 모듈 시스템 (StsvModule): 기능 단위로 켜고 끄고, 리로드
  ├─ 콘텐츠 팩: 아이템 / 가구 / 레시피 / 3D·2D 모델
  ├─ 리소스팩: 자동 빌드 + 내장 호스팅 + 접속 시 자동 전송
  └─ (예정) 시즌, 경제, 치지직, 보호, UI, 기록 ...

[stsv-tycoon], [stsv-kingdom] ...  모드 플러그인
  └─ stsv-core에 의존. 자기 모듈과 콘텐츠 팩(contents/tycoon/ 등)만 추가
```

모드 플러그인에서는 이렇게 사용합니다.
```java
STSVPlugin core = STSVPlugin.get();
core.modules().register(new TycoonModule());
core.furniture().registerBehavior("stsv:smelter", new SmelterBehavior());
```

## 2. 현재 구현됨 (v0.1)

| 기능 | 설명 |
|---|---|
| 콘텐츠 팩 | `plugins/STSV/contents/<팩>/`. 첫 실행 때 기본 팩이 자동 설치됨 |
| 커스텀 아이템 | 이름(MiniMessage), 설명, 모델, 최대 스택, 반짝임, 내구도 무한 |
| 3D 모델 | `.bbmodel`을 폴더에 넣으면 자동 변환됨 (큐브, 회전, 발광, 표시 설정) |
| 2D 모델 | `.png`를 넣으면 일반/손에 든 모양 모델이 자동 생성됨 |
| 가구 | 회전 설치, 여러 블록 크기, 충돌(배리어), 클릭 판정, 부수면 회수 |
| 가구 API | 설치/상호작용/파괴 이벤트, `FurnitureBehavior`로 기계 로직 연결 |
| 레시피 | 조합(모양/무형), 화로, 용광로, 훈연기, 모닥불, 석재 절단기 |
| 레시피 보호 | 커스텀 아이템이 바닐라 레시피 재료로 쓰이는 것을 차단 (복사 버그 방지) |
| 리소스팩 | 빌드 → SHA-1 해시 → 내장 웹서버로 배포 → 접속 시 전송. 내용이 같으면 해시도 같음 |
| 관리 | `/stsv give, browse(GUI), list, info, reload, pack` |
| 레시피 편집기 | `/stsv recipe create <id> <종류>`: 상자 GUI에 재료와 결과물을 넣고 저장하면 바로 등록 (`recipes/editor.yml`) |
| 화로 연료 | 아이템 `fuel: 3200` 또는 `/stsv fuel set <틱>` (`fuels.yml`). 커스텀 아이템은 설정한 경우에만 연료로 탐 |
| 설치 미리보기 | 가구를 들면 설치될 자리에 모델(테두리 발광)과 바닥 범위가 표시됨. 초록 = 설치 가능, 빨강 = 불가. 본인에게만 보임 |
| 앉기 | `furniture.seat` / `seats` 설정. 우클릭으로 앉고, 내리면 가구 앞쪽에 섬 |
| 전용 동작 아이템 | 활, 쇠뇌, 낚싯대, 방패, 검, 갑옷(착용 모습 포함). 바닐라 동작을 그대로 상속 |
| 기본 콘텐츠 자동 업데이트 | 새 jar로 바꾸면 기본 팩이 갱신되고, 빠진 파일은 삭제됨. 직접 수정한 파일은 보존 |
| 음식 | `food:`: 허기, 포만도, 먹는 시간, 동작, 소리, 효과, 반환 아이템, 재사용 대기시간, 추가 회복 |
| 스킨북 | `skin:`: 우클릭으로 창을 열고 도구를 넣으면 겉모습만 교체. 인챈트, 내구도 유지. `/stsv skin remove`로 해제 |
| 치장 + 옷장 | `cosmetic:`: 실제 장비 위에 보이기만 함(본인 F5 포함). 옷장 구역에서 `/옷장` → 메뉴. 치장 클릭 = 착용(착용 중이면 벗기, 미보유는 미리보기) → 메뉴가 닫히고 관전 카메라로 마네킹만 보임(몸, 손, 단축바 없음). 웅크리기 = 메뉴, 나가기 버튼 = 나가기. 메뉴가 열려 있는 동안만 모험 모드(관전 모드에서는 서버가 메뉴 클릭을 무시하기 때문). 카메라를 먼저 붙인 뒤 메뉴로 넘어가므로 첫 메뉴부터 단축바가 안 보임 |
| 옷장 메뉴 | 큰 상자(54칸). 치장 7×4 = 28칸, 넘치면 페이지(이전/다음). 칸 배치는 `cosmetics.menu` 설정 |
| 전용 UI | 폰트 글리프 배경(176×222) + 리소스팩 버튼 아이콘. 그림/설정/글리프 위치가 서로 맞는지 테스트로 확인 |
| 보스 | `bosses/*.yml`: 관절별 3D 모델(디스플레이 엔티티) + 키프레임 애니메이션(부드러운 전환, 머리가 대상을 봄) + 패턴(내려찍기, 돌진, 던지기, 경고 표시 포함) + 페이즈(모델 교체, 강화) + 보스바 + 피해량 순위 + 드롭. 판정은 보이지 않는 철 골렘 |
| 보스 연계 패턴 | `type: sequence`: 단계별 애니메이션 + 판정 + 지연(번쩍임 예고) + 이동/도약 + 잡기(구출 가능) + 충격파(점프 회피) + 안전 구역 외우기. 조건부 패턴(등 뒤, 높은 곳, 회복 시도). 판정이 실제 칼 궤적과 맞는지 테스트로 검사 |
| 가구 중복 설치 방지 | 같은 플레이어의 설치는 6틱(0.3초) 안에 한 번만 (우클릭이 두 번 들어오는 경우) |
| 치장 보유 | 계정 단위 보유 목록(`plugins/STSV/data/cosmetics.yml`, 시즌 초기화와 무관). 교환권(`voucher:`)을 우클릭해서 등록, 관리자 지급, 등급 4단계, 획득 연출. 미보유도 미리보기 가능, 착용만 불가 |
| 무기 효과 | `effects.swing`: 좌클릭(공격) 때 시선 기준 대각선(오른쪽 위 → 왼쪽 아래) 참격. `effects.charge`(선택): 우클릭 차지 후 큰 참격 |
| 움직이는 모델 | 애니메이션 텍스처, 회전 부품 |
| 가구 엔티티 절감 | 클릭 판정을 정사각 기둥 단위로 합침(2×2×1 기계 4→2, 3×3 바닥 9→1). 판정 범위, 겉모습 동일 |
| 보호 플러그인 호환 | 가구 설치 전에 BlockPlaceEvent를 발생시켜 다른 보호 플러그인의 판단을 따름 |

## 3. 공통 기능 가안 (구현 예정)

우선순위 기준: **P1** = 첫 시즌 전에 반드시 필요, **P2** = 시즌 품질을 크게 올림, **P3** = 있으면 좋음

### 시즌 관리 — P1
- 시즌 상태: `준비 → 진행(단계 1..n) → 피날레 → 종료`
- 단계별 규칙 전환 (예: 1주차 PvP 금지, 4주차 공성 개방). 규칙은 YAML로, 전환은 날짜/명령어로
- 주간 이벤트 스케줄러 (실시간 날짜 기준, 서버 재시작에도 유지)
- 시즌 종료: 기록 보관(아카이브) → 월드/데이터 초기화 → 명예의 전당에 반영

### 플레이어 프로필 & 기록 — P1
- 시즌별 통계 (처치, 사망, 생산량, 자산, 플레이 시간), 칭호, 업적
- 시즌을 넘어 남는 것: 명예의 전당, 칭호, 꾸미기 아이템
- 저장: SQLite 기본, MySQL 선택 (시즌별 스키마 분리)

### 치지직 연동 — P1
- 스트리머 계정 연결 (인게임 플레이어 ↔ 치지직 채널)
- 채팅과 후원을 실시간으로 받아 **서버 이벤트 버스**로 전달 → 각 모드가 반응
- 시청자 투표 (채팅 명령 → 집계 → 결과 이벤트)
- 안전장치: 후원 효과 상한, 쿨다운, 운영자 일시정지 스위치
- 사용 가능한 공식 API 범위와 인증 방식은 구현 직전에 치지직 개발자 문서로 확인 필요

### 스트리머 보호 — P1
- 오프라인 보호: 방송/접속 중이 아닐 때 영지와 설비 공격 불가 (또는 예고제)
- 방송 보고 찾아오기 방지: 좌표 숨김(축소된 디버그 정보), 미니맵/나침반 지연, 이름표 거리 제한
- 늦게 합류하거나 플레이 시간이 적은 스트리머 따라잡기 보정 (경험치/생산 배율)

### 커스텀 UI — P2
- 폰트 글리프 방식 GUI 배경 (상자 화면을 전용 디자인으로) — 옷장에 적용됨, 다른 메뉴도 같은 방식
- HUD: 액션바/보스바로 돈, 시즌 단계, 이벤트 타이머 표시
- 26.x 다이얼로그 API: 투표, 계약, 외교 제안, 거래 확인 창
- 모든 UI는 아트 스타일 가이드의 팔레트를 그대로 사용

### 경제 — P2 (타이쿤/경제 RP는 P1)
- 통화, 거래 기록, 상점/시장 API (가격 변동 포함)
- Vault 호환 (다른 플러그인과 연동)

### 팀 / 세력 / 영토 — P2 (왕국 쟁탈전은 P1)
- 팀, 동맹, 적대 상태
- 영토(청크 단위 점유) + 권한. 가구 설치 보호와 연동

### 하이라이트 기록 — P2
- 처치, 배신, 보스 처치, 거래 성사 같은 순간을 시간과 함께 기록
- 방송 시작 시각 기준으로 변환해서 내보내기 → 클립 편집할 때 바로 찾기

### 웹 대시보드 API — P3
- 실시간 랭킹, 영토 지도, 시즌 연표 (REST + WebSocket)

### 운영 도구 — P2
- 공지/예약 재시작/백업, 의심 행동 로그, 롤백 도구 연동

### 나중에
- 커스텀 블록 (노트블록 상태를 이용한 진짜 블록) — 필요해지면
- 애니메이션 몹/보스 — 기본 엔진은 구현됨(보스). 패턴 종류 추가, 일반 몹에도 적용

## 4. 추천 개발 순서

1. **게임 안 검증**: 용광로 설치/회전/파괴, 리소스팩 적용 (아래 미검증 항목)
2. 시즌 관리 + 프로필/기록 (모든 모드의 뼈대)
3. 치지직 연동 + 스트리머 보호 (스트리머 서버만의 핵심)
4. 커스텀 UI 프레임워크
5. 첫 모드: **타이쿤** (지금 만든 기계/레시피/가구 시스템을 가장 많이 씀)

## 5. 게임 안에서 아직 확인하지 못한 것

개발 환경에서 서버를 실행할 수 없어서, 실제 26.3 API로 컴파일하고 단위 테스트까지만 통과했습니다. 첫 실행 때 아래를 확인해야 합니다.

| 항목 | 확인 방법 | 문제가 있으면 |
|---|---|---|
| 가구 모델이 정면을 바라보는지 | 용광로를 네 방향으로 설치 | `furniture.display-yaw-offset: 180` |
| 모델과 충돌 블록 위치가 일치하는지 | 설치 후 F3+B 또는 걸어서 확인 | 모델의 `cells` 수정 |
| 불꽃과 램프가 어두운 곳에서 빛나는지 | 밤에 확인 | `light_emission` 지원 여부 확인 |
| 리소스팩 적용 | 접속해서 전송 메시지 확인 | `host.public-url`을 외부 주소로 |
| 클릭 판정이 배리어보다 우선하는지 | 가구를 좌클릭/우클릭 | 판정 크기 조정 |
| 의자에 앉은 높이 | 의자에 앉아보기 | `seat.height` 조정 |
| 방패 위치/각도 | 손에 들기, 막기(우클릭) | 모델 위치 조정 |
| 커스텀 재료가 화로 레시피에 들어가는지 | [TEST] 재료를 화로에 | ExactChoice 방식으로 변경 |
| 회전 부품이 부드럽게 도는지 | [TEST] 기계 위 팬 | `SPIN_STEP` 조정 |
| 치장이 본인 F5와 다른 사람 화면에 보이는지 | 토마토 탈 적용 후 F5, 다른 계정 | `cosmetics.show-to-self` |
| 옷장에서 마네킹이 잘 보이는지 | 옷장 구역에서 `/옷장` | 서는 거리(2.6블록) 조정 |
| 치장 상태 | `/stsv cosmetic info` | - |
| 3D 검/낚싯대/방패를 쥔 자세 | 손에 들고 1인칭/3인칭 | 모델 위치 조정 |
| 옷장 UI 배경이 칸과 딱 맞는지 | `/옷장` 메뉴에서 아이템이 칸 그림 안에 있는지 | `font/wardrobe.json` 의 `ascent`(세로), `\uf801` 이동량(가로) |
| 옷장 버튼 아이콘 | 메뉴 아래 줄 | `cosmetics.menu.custom-icons: false` 로 바닐라 아이콘 |
| 보스 모델이 판정 위치에 딱 붙어 있는지 | `/stsv boss spawn test_golem` 후 F3+B | 위아래로 뜨면 `bosses.rider-offset-adjust` |
| 보스가 바라보는 방향, 팔 휘두르는 방향 | 보스 앞에서 패턴 보기 | 애니메이션 키프레임 부호 |
| 경고 표시와 실제 판정이 맞는지 | 경고 원 안/밖에서 맞아보기 | 패턴의 `radius`, `forward` |
| 처형자 패턴 난이도 | 혼자 / 여럿이 상대해보기 | `hold`(지연 길이), `chance`(연타 확률), `turn`(추적 속도), `cooldown` |
| 충격파를 점프로 넘을 수 있는지 | 충격파 고리가 올 때 점프 | 충격파 `width`, `speed` |
| 잡힌 플레이어가 손에 붙어 있는지 | 잡기 맞아보기 | 소켓 `hand_l` 위치 |
